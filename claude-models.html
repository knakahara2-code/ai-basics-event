Claudeモデルの選び方

Fable 5 / Opus 4.8 / Sonnet 5 / Haiku 4.5 ── 具体的に何が違う？

Claudeの4モデルは同じ“脳の系統”の大小・世代違い。選ぶ軸はシンプルに 知能（自律性）・速度・コスト の3つ。 上ほど賢く高価・遅め、下ほど速く安い。迷ったら Sonnet 5（既定）でOKです。

「入 / 出」って何？ ＝ 入力トークン / 出力トークン の単価（100万トークンあたり）。
入＝あなたが読ませた分（指示＋資料＋会話履歴）、出＝AIが書いて返した分。 文章を“生成”する側が重いので、出力は入力の数倍高いのがふつう（例：Fable 5＝入 $10 / 出 $50＝5倍）。 つまり「長い資料を読ませる」より「AIに大量に書かせる」方がコストは効きます。

③ Fable 5 と Opus 4.8、実際どう違って見える？

「使っていて差が分からない」── それ、正常です。差が出る場面が限られているから。

😐 差が出にくい（＝ふだんの使い方）
短い単発プロンプト、ステップごとに指示する対話、1関数のリファクタ、仕様の決まったアルゴリズム、単一ファイルの機能追加。この領域は Opus 4.8 でほぼ頭打ちなので、Fableの上積みが見えません。
🔥 差が出る（＝Fableの独壇場）
複数ファイルにまたがる大リファクタ／モジュール境界をまたぐデバッグ／第一原理でのアーキ判断／長時間の自律実行（計画→実行→自己レビュー→反復を監督なしで継続）。SWE-Bench Pro は Fable 80.3% vs Opus 69.2%（11pt差）。
カギは「作り込んだ自律フロー」。ファイルにメモを残して自己改善させると、Fableの伸びは Opus の約3倍という報告も（長い研究タスクを36時間で他社の4日相当まで、等）。逆に素のOpusパイプラインにFableを差し替えるだけでは差は出ません。だから普段 Opus / Sonnet で足りるのは正しい判断。「長い・大きい・またぐ・任せきる」仕事だけ Fable に回すのが正解です（Fableは約2倍の価格）。
Fable 5 と Mythos 5 の関係：中身は同じモデル。Fable 5＝安全装置（分類器）つきの公開版、Mythos 5＝安全装置を外した承認パートナー限定版（一般利用は不可）。 Fable 5 は、サイバー・生物化学などの危険分類に触れた時だけ自動的に Opus 4.8 が応答します（全体の5%未満）。
“モデル選択”とは別の軸：画面には「思考レベル（例：高）」や「高速モード」もあります。これは同じモデルで、どれだけ熟考させるか／速さを優先するかの調整。 まずは Sonnet 5・思考レベル標準で十分。難しい時だけ上のモデルや「高」に上げる、という使い方が実用的です。
まとめ：賢さ順に Fable 5 ＞ Opus 4.8 ≒ Sonnet 5 ＞ Haiku 4.5、速さ・安さは逆順。 ただし Sonnet 5 が知識作業で Opus に迫るため、実務は Sonnet 5 を軸に、難所だけ Opus / Fable、量産は Haiku ── これが基本の型です。
